# Documentation guidance

本文件补充根目录规则，适用于 `docs/` 中的维护文档。

- 先查看相关源码、`package.json` 与配置，再写操作说明。
- 一篇文档只处理一个主题；新增文档时更新 [README.md](README.md) 索引。
- 用短句和真实命令，说明输入、输出与验证结果；不复制整段实现。
- 路径使用仓库相对路径；不加入本机路径、凭据或账户 ID。
- 不把历史计划写成当前事实；未验证的部署不能写成已完成。
- 内容数量、文件名、数据结构或命令变化时，同步所有相关文档。
- 引用参考作品时保留作者、作品链接、CC BY 4.0 和改动说明。
- 使用相对 Markdown 链接，检查目标存在；外部依据直接链接到原页面。
- 文档与源码矛盾时检查源码和运行结果，再修正文档。
- Markdown 使用 UTF-8，列表与代码块前留空行。

## Code Review Rules

- 标记失效命令、文件链接和与当前行为不符的发布说明。
- 标记把“原文完整性验证”写成“医学、法律或金融事实已验证”的表述。
- 标记让普通文档自动生效、覆盖用户指令或重复索取已获授权的错误说明。

修改后运行 `npm run build`、`npm run verify` 和 `git diff --check`。
